# Film Asset Generator
# 影视资产自动生成 Skill

版本：1.1

---

# 1. 核心任务

本 Skill 是一个影视项目资产自动生成工作流。

用户提供：

1. 剧本文件；
2. 资产文件；

或者提供一个同时包含剧本和资产文件的项目文件夹。

必须完成：

读取剧本
→ 读取资产文件
→ 理解剧情
→ 建立项目 World Bible
→ 提取资产
→ 分类资产
→ 合并重复资产
→ 建立生成任务
→ 构建每张图片完整提示词
→ 调用图片生成执行器
→ 生成人物 / 场景 / 道具
→ 自动质检
→ 自动查重
→ 不合格自动重生
→ 保存最终文件
→ 记录进度
→ 支持中断续跑
→ 输出最终项目报告。

本 Skill 的目标不是简单根据资产描述生图。

必须：

“先理解整部剧的时代、地区、社会背景、世界观和视觉体系，再生成属于这个世界的资产。”

---

# 2. 最高原则

以下规则优先级不可修改。

## 信息优先级

从高到低：

1. 资产文件中的明确硬性描述
2. 剧本中对当前资产的明确描述
3. 剧本整体时代、背景和 World Bible
4. 根据剧情上下文进行的合理推导
5. 模型自由设计

核心规则：

ASSET FILE EXPLICIT CONSTRAINTS > ALL OTHER SOURCES

资产文件中的明确要求拥有最高优先级。

禁止：

- 用剧本覆盖资产文件明确要求；
- 用 World Bible 覆盖资产文件明确要求；
- 为了“更合理”擅自修改资产描述；
- 为了美观修改明确颜色；
- 擅自更换明确服装；
- 擅自修改明确年龄；
- 擅自改变明确材质；
- 擅自删除明确场景元素。

示例：

资产文件：

“深灰色开领衬衫”

剧本：

“白色衬衫”

最终必须：

深灰色开领衬衫。

如果资产要求传统木制办公桌，而世界观是高度未来都市，也必须保留木制办公桌。

可以将未被锁定的细节未来化，但不能把木桌改成金属桌。

# 3. 自动补全原则

资产文件未明确描述的视觉信息，可以根据：

- 剧本；
- 人物身份；
- 人物性格；
- 社会阶层；
- 所在地区；
- 年代；
- World Bible；
- 当前剧情用途；

自动合理补全。

不需要因为普通视觉细节逐项询问用户。

例如可以自动补：

- 发型细节；
- 发色细节；
- 面料；
- 服装版型；
- 鞋；
- 普通首饰；
- 家具次要材质；
- 墙体材质；
- 普通灯具；
- 合理空间结构。

但是不得无依据添加会改变角色定义的强视觉特征，例如：

- 刀疤；
- 大面积纹身；
- 机械义眼；
- 义肢；
- 异瞳；
- 明显毁容；
- 特殊疾病外观；
- 大面积身体改造；
- 强烈宗教符号；
- 其他会形成新剧情设定的元素。

# 4. 输入方式

必须同时支持两种工作模式。

## MODE A：直接附件模式

用户直接把两个文件交给 Codex：

- 剧本
- 资产文件

Skill 自动识别哪个是剧本、哪个是资产文件。

如果可以可靠判断，不得询问。

只有无法可靠判断时才询问用户。

项目名称：

优先读取剧本正式标题。

如果无法识别正式标题：

使用剧本文件名作为项目名称。

输出到：

当前工作目录/
    项目名称/
        生成资产/

---

## MODE B：项目文件夹模式

用户提供一个项目文件夹。

Skill 扫描项目目录并识别：

- 剧本；
- 资产文件；
- 已有生成记录；
- World Bible；
- 任务进度；
- 角色定稿记录。

输出到：

项目目录/
    生成资产/

如果发现已有进度：

必须优先进入断点续跑模式。

禁止从头重复生成已经 PASSED 的资产。

# 6. 文件读取策略

优先使用结构化、非破坏性解析。

TXT / MD：
直接读取文本。

DOCX：
读取段落、表格和标题结构。

XLSX：
读取工作表、表头、单元格和备注。

CSV：
保持原始行列关系读取。

PDF：
优先文本层解析。

如果 PDF 为扫描文件或正常文本解析明显缺失内容，再使用图像识别/OCR方案。

RTF：
读取其实际富文本内容，不只读取控制字符。

提取后保存规范化中间数据。

# 7. World Bible

第一次处理项目时，必须先读取完整剧本并建立：

World_Bible.md

World Bible 至少分析：

- 故事年代；
- 时间范围；
- 国家；
- 地区；
- 城市；
- 现实世界 / 架空世界；
- 社会背景；
- 社会阶层；
- 科技水平；
- 经济水平；
- 建筑体系；
- 室内体系；
- 家具体系；
- 日常用品；
- 交通工具；
- 服装体系；
- 材质体系；
- 色彩体系；
- 灯光体系；
- 摄影风格；
- 环境状态；
- 不同社会阶层之间的视觉区别；
- 禁止出现的时代错误元素；
- 项目重要视觉关键词；
- 剧情中特殊视觉规则。

World Bible 是项目级视觉标准。

后续所有资产必须引用同一份 World Bible。

禁止：

每一批重新自由理解剧本。

禁止：

每张图重新建立一个世界观。

# 8. World Bible 更新机制

记录：

- 剧本文件哈希；
- 资产文件哈希；
- World Bible 版本。

如果源文件发生变化：

先检查具体变化内容。

默认：

局部更新。

例如只修改某个角色服装：

只更新这个人物相关任务。

不得重做无关场景和道具。

如果发生以下重大修改：

- 故事年代改变；
- 国家改变；
- 世界类型改变；
- 科技体系改变；
- 核心建筑体系改变；
- 核心美术体系改变；
- 整体视觉世界观改变；

则重新分析 World Bible。

已有且不受影响的 PASSED 资产不得无理由重新生成。

# 10. 重复资产合并

如果同一个资产在文件中重复出现：

不得直接重复生成。

先判断它是不是：

同一资产的重复描述。

如果是：

合并描述。

例如：

第一次：

“黑色专业录音笔”

第二次：

“顶部红色录制灯，边缘有磨损”

合并为同一个完整资产。

但是如果明确属于：

- 不同状态；
- 不同版本；
- 不同年龄；
- 不同服装；
- 不同时间；
- 不同损坏程度；
- 剧情要求的不同形态；

则保留为不同资产。

例如：

完整王冠
破损王冠

属于两个资产。

# 13. 全局图片规格

所有最终图片统一：

2048 × 1152

比例：

16:9 横屏

格式：

PNG

必须检查最终文件实际尺寸。

不得只通过文件名宣称是 2048×1152。

如果图片生成执行器无法原生输出该尺寸：

优先生成最高质量的 16:9 或最接近目标的高分辨率图。

然后转换为：

2048×1152 PNG。

禁止非等比拉伸人物或建筑。

最终图片不得出现明显比例变形。

# 14. 人物生成总规则

每个新人物：

首先生成 5 个不同演员候选。

即：

Candidate 01
Candidate 02
Candidate 03
Candidate 04
Candidate 05

这不是同一个人的五个镜头。

必须明显表现为：

5个不同真人演员。

五个人：

脸型和五官必须明显不同。

但是必须保持：

- 同一角色年龄段；
- 同一性别；
- 同一族裔 / 地域要求；
- 同一职业；
- 同一社会阶层；
- 同一角色气质；
- 同一基础身材类型；
- 同一时代；
- 同一世界观；
- 同一服装类别。

禁止通过以下方式伪造“不重复”：

- 单纯换发型；
- 单纯换妆；
- 单纯换表情；
- 单纯换灯光；
- 单纯换肤色；
- 极端改变胖瘦；
- 极端改变年龄；
- 擅自改变族裔；
- 换成完全不同角色气质。

# 16. 主要角色颜值与镜头吸引力硬规则

对于男主、女主、核心主要角色、重要反派及其他被剧本或资产文件认定为“主要角色”的人物，默认执行高颜值真人选角标准。

本规则仅在资产文件和剧本没有明确要求相反形象时生效。

核心原则：

在不违反角色年龄、性别、族裔 / 地域、职业、社会阶层、剧情身份、时代背景、世界观和资产硬性描述的前提下，主要角色默认应优先生成：

- 帅气；
- 美丽；
- 漂亮；
- 上镜；
- 有明星感；
- 有高级感；
- 有辨识度；
- 有角色记忆点；
- 皮肤状态好；
- 五官协调；
- 脸部轮廓清晰；
- 气质好；
- 精神状态好；
- 整体具有明显镜头吸引力。

对男性主要角色：

默认追求“英俊、立体、轮廓清晰、比例协调、上镜、有气场、有辨识度”，而不是普通路人脸。

可以根据角色身份选择不同类型的高颜值方向，例如：

- 冷峻精英型；
- 成熟权势型；
- 贵公子型；
- 阳光俊朗型；
- 痞帅型；
- 禁欲型；
- 危险迷人型；
- 文雅高级型；
- 强势领袖型。

但不得为了“帅”而改变剧本明确的年龄、族裔、职业、阶层或人物性格。

对女性主要角色：

默认追求“漂亮、精致、五官协调、脸型优美、皮肤状态好、上镜、高级、有气质、有辨识度”，而不是普通路人脸。

可以根据角色身份选择不同类型的高颜值方向，例如：

- 明艳型；
- 清冷型；
- 高级御姐型；
- 温柔精致型；
- 甜美型；
- 冷艳型；
- 知性型；
- 贵气型；
- 危险迷人型；
- 强势女王型。

但不得为了“漂亮”而改变剧本明确的年龄、族裔、职业、阶层或人物性格。

## 主要角色皮肤标准

除非资产文件或剧本明确要求：

- 病态；
- 衰老；
- 严重晒伤；
- 大面积痘痘；
- 疤痕；
- 伤口；
- 污泥；
- 极度疲惫；
- 长期流浪；
- 特殊皮肤状态；

否则主要角色默认采用健康、干净、真实、适合电影摄影的真人皮肤状态。

要求：

- 真实皮肤纹理；
- 毛孔自然存在；
- 肤质细腻但不能磨皮成塑料；
- 无明显油腻反光；
- 无廉价美颜滤镜感；
- 无蜡像感；
- 无塑料皮肤；
- 无过度磨皮；
- 面部干净；
- 肤色自然；
- 五官区域清晰；
- 在超写实摄影中仍然保持好皮肤和高颜值。

“皮肤好”不等于：

- 完全没有毛孔；
- 陶瓷皮肤；
- 塑料皮肤；
- 强烈磨皮；
- AI美颜脸。

目标是：

“真实真人中的高质量皮肤状态 + 影视级上镜效果”。

## 主要角色辨识度

主要角色的高颜值不能变成千篇一律的标准AI网红脸。

5个候选都必须：

- 好看；
- 上镜；
- 具有明确人物魅力；

同时还必须：

- 脸型不同；
- 五官组合不同；
- 轮廓不同；
- 眼型、鼻型、嘴型、眉骨等具有明显区别；
- 每个人都有自己的演员辨识度。

禁止：

为了生成“漂亮”而让5个候选变成几乎相同的网红脸。

禁止：

为了生成“帅”而让5个候选都变成同一种模板化男模脸。

目标应是：

“5名都足够好看的不同演员，而不是同一张漂亮脸的5个变体”。

## 与剧本明确形象要求的优先关系

本规则不能覆盖资产文件或剧本中的明确人物形象要求。

例如剧本明确要求：

- 长相普通；
- 丑陋；
- 猥琐；
- 苍老；
- 肥胖；
- 憔悴；
- 病态；
- 面部有明显伤疤；
- 长期营养不良；
- 脏乱；
- 特殊畸形；
- 明显不修边幅；

则必须按照明确要求执行。

不得为了“主要角色必须漂亮”而擅自美化到破坏人物设定。

但是：

如果剧本只是写：

“35岁集团CEO”

而没有写长相普通、丑陋或其他限制，

则默认：

在满足35岁、集团CEO、性格和世界观要求的基础上，

优先生成：

“非常英俊、上镜、气质高级、有权势感、有角色辨识度的35岁男性”。

如果剧本只是写：

“28岁集团继承人女性”

而没有明确限制外貌，

则默认：

优先生成：

“非常漂亮、上镜、皮肤好、气质高级、有身份感、有角色辨识度的28岁女性”。

## 提示词硬性表达

# 66. 最终完成条件

一个资产只有同时满足：

1. 正确生成；
2. 文件真实存在；
3. PNG有效；
4. 尺寸为2048×1152；
5. 符合资产硬性描述；
6. 符合项目世界观；
7. 通过质量检查；
8. 通过重复 / 一致性检查；
9. 已写入质检记录；

才能：

status = PASSED

# 67. 禁止行为

本 Skill 严禁：

只写生图提示词但声称生成完成；

建立空PNG；

建立占位图片；

用同一张图片复制改文件名凑数量；

人物5张只换发型；

场景3张只换摄影机角度；

后面的图片降低质量；

跳过质检；

遗漏资产硬性描述；

擅自修改资产文件要求；

错误覆盖已通过资产；

失败时从头重跑整个项目；

API失败后偷偷切换低质量模型；

把临时图当最终图；

用不合格结果凑齐数字；

为了速度减少提示词内容。

# 68. 用户交互原则

尽可能自动执行。

不要因为普通小细节频繁提问。

可以自动推导：

自动推导。

必须用户决定时：

才询问。

典型需要用户决定：

- 两个输入文件无法判断类型；
- 多套人物造型但没有基础造型；
- 人物5个演员候选需要定稿；
- 资产文件自身存在无法同时满足的互斥硬要求；
- provider需要用户凭证或配置且当前环境没有；
- 用户明确要求更改世界观核心规则。

多个问题可以同时询问时：

合并询问。

不要一个问题问一次。

# 71. 每次重新运行时

不要直接开始生图。

首先：

1. 检查是否存在已有项目配置；
2. 检查源文件hash；
3. 检查 World Bible；
4. 检查 task_state；
5. 检查 PASSED 文件真实存在；
6. 检查 casting_lock；
7. 检查 provider配置。

然后确定：

NEW PROJECT

或：

RESUME PROJECT

或：

INCREMENTAL UPDATE。

# 72. 视觉判断优先

人物重复和场景重复：

不能单纯使用像素差异。

应优先采用：

语义视觉判断。

可以辅以：

- 图像embedding；
- perceptual similarity；
- 人脸结构比较；
- 布局特征；
- 图像特征相似度。

但是：

“像素不同”

不代表：

“设计不同”。

例如同一个办公室换一个角度：

仍然算同一设计。

---

# 73. 质量检查优先级

当“数量”和“质量”发生冲突：

质量优先。

宁可：

4张人物 PASSED + 第5张 NEEDS_REVIEW

也不能：

强行保存第5张烂图并声明完成。

宁可：

场景只有2个真正不同方案，

也不能把第3张重复空间冒充新方案。

---

# 74. 世界观一致性与差异性关系

不同资产：

必须属于同一个世界。

但是：

不得因此把全部场景做成一模一样。

统一的是：

- 世界观；
- 技术逻辑；
- 材质体系；
- 时代；
- 社会背景；
- 美术语言。

变化的是：

- 不同地点功能；
- 空间布局；
- 建筑设计；
- 家具结构；
- 场景视觉中心；
- 具体设计。

目标：

“看起来属于同一部剧，但绝不是同一个房间复制粘贴。”

# 77. 最终执行原则

永远牢记：

资产文件决定：
生成什么，以及明确要求必须是什么。

剧本决定：
它为什么存在，以及它属于什么世界。

World Bible决定：
整个项目如何保持视觉统一。

资产类型模板决定：
最终图片如何标准化交付。

Quality Baseline决定：
第1张到最后1张都维持相同质量等级。

Task State决定：
任务中断以后从哪里继续。

Casting Lock决定：
同一个人物后续永远保持同一个正式演员身份。

Main Character Beauty Standard决定：
在没有明确反向人物设定时，主要角色始终优先采用高颜值、上镜、皮肤状态好、气质高级、具有鲜明辨识度的真人演员形象。

最终目标不是“尽快把数量凑齐”。

最终目标是：

生成一整套真正可以进入影视制作流程使用的、
统一世界观、
可追溯、
高质量、
无明显重复、
可持续扩展、
可断点续跑的影视资产库。
